# 패키지 취약점 분석

저장된 패키지 입력과 Ubuntu 공식 CVE 기록을 대조해 버전 비교, 최종 판단, 확인할 이유와 공식 근거를 저장합니다. Ubuntu 22.04·24.04의 `apache2`, `mysql-8.0` 소스 패키지가 대상입니다. 단순 버전 비교와 실제 설치 환경의 영향 판단을 구분합니다.

## 사용 순서

1. API·웹·Worker를 실행합니다. 기존 DB에는 `alembic upgrade head`로 `0004`를 적용합니다. `scripts/dev.py`는 시작 시 마이그레이션을 수행합니다.
2. **자산 현황**에서 자산을 등록하고 패키지 JSON을 저장하거나 [SSH 수집](ssh-collection.md)으로 가져옵니다.
3. **보안 자료**에서 입력과 같은 Ubuntu 릴리스·패키지 자료를 가져옵니다. 필요한 NVD CVE, CISA KEV, Apache·Oracle 공지도 수집합니다.
4. **취약점 분석**에서 자산과 패키지 입력 이력을 선택하고 **분석 실행**을 누릅니다.
5. 분석 이력에서 완료 상태를 확인하고 패키지명·CVE·판단 상태로 검색합니다.
6. **근거 보기**에서 대조 버전, 설치 출처, 판단 이유, CVSS·KEV와 당시 출처를 확인합니다. **저장 원문 보기**는 텍스트로 표시하고 전체 원문을 내려받을 수 있습니다.

자료를 수집하지 않아도 분석 요청은 가능하지만 `대조 자료 없음`으로 남습니다. 분석이나 결과 조회가 외부 API 수집을 자동 실행하지 않습니다. 비활성 자산은 새 분석을 요청할 수 없으며 이전 결과는 조회할 수 있습니다.

## 버전 비교와 최종 판단

Ubuntu OSV의 `fixed`는 소스 패키지 버전입니다. 따라서 입력의 `source_name`과 `source_version`을 대조합니다. 소스 정보가 없을 때 바이너리 버전으로 대신 판정하지 않습니다. 소스 패키지명이 없는 알려진 바이너리 이름은 후보 자료를 찾는 데만 사용합니다. [Ubuntu OSV 의미](https://documentation.ubuntu.com/security/security-updates/osv/), [Debian 버전 규칙](https://www.debian.org/doc/debian-policy/ch-controlfields.html#version).

현재 공식 자료 연결은 단일 `ECOSYSTEM / introduced: 0 → fixed` 범위만 자동 비교합니다. epoch, 배포판 수정 번호와 `~`를 포함한 전체 버전을 비교합니다. Apache 제품 자체의 수정 버전, NVD 점수와 Oracle 제품 버전으로 Ubuntu 기준을 대체하지 않습니다.

| 항목                                               | 처리                                       |
| -------------------------------------------------- | ------------------------------------------ |
| 설치 소스 버전 < 공식 수정 버전                    | `BELOW_FIX` / 수정 기준보다 낮음           |
| 설치 소스 버전 ≥ 공식 수정 버전                    | `MEETS_FIX` / 수정 기준 이상               |
| 버전 누락·잘못된 형식·복잡한 범위·철회             | `UNAVAILABLE` / 비교 불가                  |
| 출처 미검증·OS 예상값 불일치·NVD 기각·규칙 상충    | 최종 판단 `NEEDS_REVIEW`                   |
| 수정 전 버전의 제품 컴포넌트·설정 조건 미확인      | 최종 판단 `NEEDS_REVIEW`                   |
| 검증된 출처·동일 릴리스·유효한 공식 수정 기준 충족 | `FIXED` / 해당 CVE의 패키지 수정 기준 충족 |

**현재 JSON 업로드의 출처는 `USER_DECLARED` 또는 `UNKNOWN`입니다. 따라서 실제 업로드 분석에서는 수정 기준을 충족해도 최종 판단은 `추가 확인 필요`로 남습니다.** JSON에서 검증 상태나 검증 근거를 직접 지정할 수 없습니다. 시험 입력은 별도로 가상 배지를 표시하며 이를 실제 출처 검증으로 승격하지 않습니다.

**SSH 수집도 설치 출처는 `UNKNOWN`으로 유지합니다.** SSH 인증과 패키지 DB 조회는 실제 설치 출처·서명·파일 무결성을 증명하지 않습니다. 직접 수집했다는 이유로 확정 판단으로 바꾸지 않습니다.

엔진의 `AFFECTED`, `NOT_AFFECTED`는 모든 적용 조건을 만족한 규칙 또는 명시적 비영향 규칙에 한해서만 사용합니다. 현재 OSV 변환은 비영향 규칙을 만들어내지 않으며, 수정 전 버전의 런타임 조건을 자동 해석하지 않습니다. NOT_AFFECTED는 가상 규칙으로만 검증했습니다. AFFECTED는 아래의 제한된 실제 HTTP/2 사례도 검증했습니다. 나머지 CVE의 실행 조건은 별도 확인 대상입니다.

`FIXED`도 특정 CVE의 설치 패키지 기준이며 서비스 재시작, 실행 중인 프로세스의 코드, 자산 전체의 안전을 뜻하지 않습니다. 악용 가능성 시험이나 자동 패치를 수행하지 않습니다.

## 판정과 처리 상태

`OUT_OF_SCOPE`, `NO_MATCHING_RECORD`, `NOT_INSTALLED`, `PARTIAL_COLLECTION`, `COLLECTION_FAILED`에는 취약 여부 판정값을 붙이지 않습니다. OSV 기록 부재, 미수집, 오류는 영향 없음의 근거가 아닙니다.

현재 범위의 두 소스 패키지 중 입력에 없는 대상은 전체 목록으로 선언되고 패키지 식별 정보도 갖춰진 경우에만 `입력 목록에 없음`으로 표시합니다. 부분 목록이나 소스 식별이 불완전한 목록에서는 `설치 여부 미확인`으로 표시합니다. 이는 입력 목록의 선언을 바탕으로 한 처리이며 실제 서버에서 부재를 확인했다는 뜻은 아닙니다.

NVD의 CVSS 공급자·버전·벡터·점수를 보존합니다. 숫자 점수 미제공은 0과 구분합니다. CISA는 `등재`, `저장 목록에 미등재`, `자료 미수집`으로 구분하며, 미등재를 악용 없음으로 해석하지 않습니다. 관련 공지는 해당 CVE의 보충 자료이며 Ubuntu 판정 규칙에 모두 사용됐다는 뜻은 아닙니다.

## 입력 고정과 저장

분석 접수 시 다음을 고정합니다.

- 자산 이름·예상 OS, 입력 스냅샷 ID와 가상 여부
- 출처·수집 범위별 최신 성공 저장본 중 해당 릴리스의 Ubuntu 자료, 관련 CVE의 NVD·Oracle 자료, Apache와 KEV 기준본 ID
- 자료의 최근 갱신 실패·진행 상태에 대한 경고와 판정 규칙 버전

그 뒤 자료가 갱신되거나 작업이 대기해도 고정된 ID만 사용합니다. 이력과 상세 조회도 최신 자료를 섞지 않습니다. 더 최신 자료를 적용하려면 새 분석을 실행합니다. 자료의 유효 기간을 임의로 정하지 않고 실제 수집 시각을 표시합니다.

`analyses`에는 입력·규칙·출처 ID, 정규화한 `FeedSnapshot`, 경고와 결과 요약을 저장합니다. `findings`에는 패키지·CVE별 비교·판단·이유·규칙·원문 참조·CVSS·KEV를 저장합니다. 관련 자료는 고정한 기존 `source_records`·`source_documents`를 조회합니다.

분석 결과 전체와 작업 성공 상태는 같은 트랜잭션으로 저장합니다. 오류 시 새 결과를 부분 공개하지 않으며 이전 분석은 유지합니다. Worker 재시작 전에 저장을 완료한 결과는 성공으로 유지하고, 미완료 작업은 `WORKER_RESTARTED` 실패로 표시합니다. 규칙 버전이 접수 후 바뀌면 `RULESET_CHANGED`로 실패시켜 다른 규칙으로 조용히 재분석하지 않습니다.

한 분석은 기준본 최대 2,000개, 결과 최대 20,000건으로 제한합니다. 기준본은 저장되어 있는 자료를 선택하므로 자동 전체 CVE 수집을 보장하지 않습니다.

## API

모든 경로는 `/api/v1` 기준이며 개발용 토큰이 필요합니다.

| 메서드 | 경로             | 동작                                                                                         |
| ------ | ---------------- | -------------------------------------------------------------------------------------------- |
| POST   | `/analyses`      | `{"inventory_id":"UUID"}`, `Idempotency-Key` 필수. 고정된 분석 입력과 작업 정보를 202로 반환 |
| GET    | `/analyses`      | `asset_id` 선택 필터, 분석 이력·작업 상태·출처·요약                                          |
| GET    | `/analyses/{id}` | 한 분석의 입력·출처·상태·경고                                                                |
| GET    | `/findings`      | `analysis_id`, `asset_id`, `verdict`, `processing_status`, `search` 필터                     |
| GET    | `/findings/{id}` | 저장 결과와 그 분석 당시의 관련 출처·KEV 기준본                                              |

목록은 `limit` 1~100, `offset` 0 이상이며 기본 20건입니다. UI는 한 분석을 선택해 조회합니다. API에서 `analysis_id`를 생략하면 과거 분석도 포함하므로 최신 자산 상태로 해석하면 안 됩니다.

`전체 결과`의 표시 순서는 영향 있음 → 추가 확인 필요 → 수정 기준 충족 → 영향 없음 → 수집 실패 → 설치 여부 미확인 → 대조 자료 없음 → 입력 목록에 없음 → 지원 범위 밖입니다. 같은 상태는 CVE 번호·패키지 이름·결과 ID 순으로 정렬합니다. 검색·페이지 이동에도 API에서 이 순서를 적용합니다. 표시 순서이며 판정값이나 위험도 점수를 변경하지 않습니다.

동일 요청 키·동일 인벤토리는 기존 분석을 반환합니다. 같은 키를 다른 인벤토리나 작업에 재사용하면 409입니다. 새 키는 같은 입력에 대한 새로운 분석 이력을 생성합니다. 이전 미구현 계약의 `feed_snapshot_id` 요청 필드는 받지 않으며 서버가 출처 선택과 기준 ID를 관리합니다.

## 파일 검증·대응·비교 연결

SSH 기록에서 공식 파일 검증을 마친 새 인벤토리는 일치한 패키지에 OFFICIAL_MATCH를 부여합니다. 이 기록으로 새 분석을 실행하면 출처 확인 제한을 해소할 수 있습니다. 동일 CVE의 수정 버전 이상이며 다른 제한이 없다면 FIXED가 가능합니다. 이것은 파일·소스 버전 기준 판단이며 서버 전체의 안전이나 런타임 상태를 보장하지 않습니다.

새 분석은 `ubuntu-packages/1.1` 규칙과 CVE별 remediation을 저장합니다. 이전 분석은 변경하지 않습니다. 대응 우선순위·공식 수정 기준·확인 절차는 결정적 규칙으로 생성합니다. 다른 인벤토리와 비교할 때는 기준 분석의 자료로 양쪽을 평가합니다. [질문·대응·비교 상세](insights-comparisons.md).

## 제한된 실제 HTTP/2 적용 조건

규칙 `ubuntu-packages/1.2`는 CVE-2024-27316·Ubuntu 24.04 amd64·apache2-bin의 공식 `2.4.58-1ubuntu8` 설치 파일과 실행 프로세스·모듈·HTTP/2 응답이 함께 확인된 경우 AFFECTED를 허용합니다. 조건은 일반적인 버전 비교의 대체 수단이 아니며 다른 CVE·버전에 적용하지 않습니다. 관측이 없으면 NEEDS_REVIEW를 유지하고, 수정 버전은 기존 규칙으로 FIXED를 판단합니다. [실제 시험과 관측·원복 방법](affected-demo.md).
