# 공식 CVE 자료 수집·저장·조회

보안 자료 화면에서 Ubuntu, NVD, CISA KEV, Apache와 Oracle의 자료를 가져와 CVE 번호로 연결합니다. 자료별 원문·출처·수집 시각·SHA-256·해석 코드 버전을 보존합니다. 이 화면은 자료 관리 기능입니다. 저장한 자료를 패키지와 비교하려면 별도의 [취약점 분석](assessment.md)을 실행하세요.

## 출처와 범위

| 출처       | 수집 범위                                                   | 저장하는 주요 정보                                                                                |
| ---------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Ubuntu CVE | Ubuntu 22.04/24.04 LTS의 `apache2`, `mysql-8.0` 소스 패키지 | CVE 설명, 릴리스별 버전 범위·영향 버전, 수정 기준, Ubuntu 우선순위, 제공되는 CVSS 벡터, 공식 링크 |
| NVD        | 사용자가 입력하거나 상세 화면에서 선택한 CVE 1개            | 설명, 공급자별 CVSS 버전·점수·벡터, CWE, NVD 처리 상태, 공개·수정 시각과 참고 링크                |
| CISA KEV   | 공개된 전체 악용 확인 목록                                  | CVE, 제품, 등재일, 권고 조치, 랜섬웨어 악용 확인 정보                                             |
| Apache     | HTTP Server 2.4 공식 취약점 공지                            | CVE별 설명·영향 조건, 제품 자체 수정 버전, 공지 표                                                |
| Oracle     | 선택한 공식 보안 공지의 MySQL Risk Matrix                   | CVE별 제품·컴포넌트·프로토콜·영향 버전 등의 원문 행                                               |

Ubuntu 자료는 Canonical이 제공하는 OSV 기록을 [OSV API](https://google.github.io/osv.dev/api/)로 조회합니다. Ubuntu의 [OSV 설명](https://documentation.ubuntu.com/security/security-updates/osv/)에 공식 배포 경로와 필드 의미가 나와 있습니다. `UBUNTU-CVE-…` 기록을 대상으로 하며 USN 링크는 보존하지만 USN 본문·OVAL 전체 해석은 아직 별도 구현하지 않았습니다.

NVD는 [공식 CVE API](https://services.nvd.nist.gov/rest/json/cves/2.0?cveId=CVE-2023-25690)를 사용합니다. 키가 없어도 조회할 수 있고, 키를 사용할 때는 로컬 `.env`의 `NVD_API_KEY`를 설정하고 API와 Worker를 재시작합니다. 키는 브라우저에 전달하지 않으며 실제 값은 코드·로그에 넣지 않습니다. 클라이언트는 키 없이 최소 6.2초, 키가 있으면 최소 0.7초의 요청 간격을 둡니다. 429 응답은 실패로 기록하고 기존 자료를 유지합니다.

CISA는 공식 JSON 피드를 사용하며, 네트워크·HTTP 실패 시 [CISA 공식 GitHub 미러](https://github.com/cisagov/kev-data)의 JSON을 시도합니다. 실제 사용한 주소는 기록에 남습니다. 자료 형식 오류는 다른 출처의 정상 결과로 덮지 않습니다.

[Apache 공지](https://httpd.apache.org/security/vulnerabilities_24.html)는 HTML의 CVE별 설명과 표를 읽습니다. [Oracle 공지](https://www.oracle.com/security-alerts/)는 `https://www.oracle.com/security-alerts/…html` 형식의 선택한 공지만 받습니다. CVE의 참고 링크 중 해당 주소가 있으면 상세 화면의 **이 공지 가져오기**로 요청할 수 있습니다. 전체 Oracle 사이트를 자동 탐색하지 않습니다. MySQL 표를 찾지 못하거나 표 구조가 달라지면 실패로 기록합니다.

## 사용 순서

1. `make dev` 또는 `python scripts/dev.py`로 API·웹·Worker를 시작합니다. `--no-worker`로 시작하면 수집 작업은 대기 상태입니다.
2. 개발 토큰으로 연결하고 **보안 자료** 메뉴를 엽니다.
3. Ubuntu 릴리스와 패키지를 선택한 뒤 **Ubuntu CVE 가져오기**를 누릅니다.
4. NVD에는 CVE 번호를 입력합니다. CISA·Apache는 각각의 가져오기 버튼으로 수집합니다. Oracle은 공지 URL을 지정합니다.
5. 작업이 완료되면 목록을 출처·CVE 번호로 필터링하고 CVE를 선택합니다. 동일 CVE의 다른 출처 자료는 상세 화면에서 함께 나타납니다.
6. **저장 이력**에서 이전 기준본을 선택할 수 있습니다. 과거 기준본의 상세는 당시 자료만 표시합니다.
7. **공식 출처 · 저장 원문**에서 링크·해시·기준본을 확인하고 원문을 텍스트로 보거나 내려받습니다. HTML 원문을 실행하지 않습니다.

수집은 사용자의 요청 때만 시작합니다. 화면 진입·조회·검색이 외부 수집을 자동 실행하지 않습니다. 각 출처는 독립 작업이므로 하나가 실패해도 다른 출처와 이전 저장 자료를 조회할 수 있습니다.

## 해석 원칙

- 목록의 **수정 기준 있음**은 공식 자료에 패치 기준이 있다는 뜻이며, 자산이 수정됐다는 판정이 아닙니다.
- Ubuntu의 단일 `introduced: 0 → fixed` 범위만 단일 수정 버전으로 표시합니다. 복잡한 범위는 그대로 보존하고 추가 확인으로 표시합니다.
- 수정 버전 미제공·다른 릴리스에만 존재하는 자료·철회 기록을 ‘영향 없음’으로 바꾸지 않습니다. OSV에 없는 패키지/릴리스를 비영향 근거로 사용하지 않습니다.
- Ubuntu의 수정 버전과 Apache의 제품 자체 수정 버전을 섞지 않습니다. NVD·Oracle 정보는 Ubuntu 패키지의 수정 여부를 단독으로 확정하지 않습니다.
- CVSS 점수가 없으면 미제공으로 표시합니다. CVSS 벡터만 있는 경우 숫자 점수를 임의 생성하지 않습니다. 서로 다른 공급자의 점수는 공급자를 표시해 각각 보존합니다.
- KEV는 **등재 / 저장된 목록에 미등재 / 아직 가져오지 않음**을 구분합니다. 미등재는 악용이 없다는 뜻이 아닙니다. 기준 시각은 실제 가져온 시각을 표시합니다.
- 제품 공지의 조건을 설명에 보존하며, 설치 설정이 이 조건을 충족하는지는 후속 판정 단계에서 확인해야 합니다.
- 화면의 최신은 **출처·수집 범위별 가장 최근 저장본**입니다. 자동 실시간 갱신이나 전 세계 CVE 전체 수집을 의미하지 않습니다.

## 저장과 실패 처리

`0003_security_sources` 마이그레이션은 다음 테이블을 추가합니다.

| 테이블               | 역할                                                |
| -------------------- | --------------------------------------------------- |
| `source_runs`        | Worker 작업의 출처와 입력 범위                      |
| `security_snapshots` | 성공한 수집의 기준본, 건수, 해석 코드 버전          |
| `source_documents`   | 원문 문자열, 실제 요청 URL, 수집 시각, 원문 SHA-256 |
| `source_records`     | CVE별 출처 기록. 각 원문·기준본에 연결              |

해시는 HTTP 압축 해제 후 UTF-8 원문 바이트 기준입니다. 원문 문자열을 UTF-8로 인코딩해 다시 확인할 수 있습니다. 모든 페이지의 수집·검증이 성공해야 자료 기준본과 성공 작업 상태를 같은 DB 트랜잭션으로 저장합니다. 중간 페이지 실패, 형식 변경, 상충 레코드가 있으면 신규 기준본을 공개하지 않습니다.

응답당 최대 20 MiB, Ubuntu 조회 최대 10페이지, 작업당 정규화 기록 최대 10,000건으로 제한합니다. 연결·읽기 제한 시간을 설정하고 인증서 검증을 사용합니다. 미등록 주소나 리디렉션을 따라가지 않습니다. 재시작 시 미완료 작업은 기존 Worker 정책에 따라 실패로 표시하며 자동 재시도하지 않습니다.

같은 `Idempotency-Key`로 같은 요청을 다시 보내면 기존 작업을 반환합니다. 다른 요청에 같은 키를 쓰면 409입니다. 같은 범위에 대기·실행 작업이 있으면 중복 접수를 줄이기 위해 기존 작업을 반환합니다. SQLite는 기존 실행 정책대로 Worker 하나를 사용합니다.

## API

모든 경로는 `/api/v1` 기준이며 개발용 Bearer 토큰이 필요합니다.

| 메서드 | 경로                               | 동작                                                             |
| ------ | ---------------------------------- | ---------------------------------------------------------------- |
| GET    | `/sources/status`                  | 다섯 출처의 최근 작업과 성공 저장본, NVD 키 설정 여부            |
| POST   | `/sources/{source_id}/sync`        | `Idempotency-Key` 필수. 작업 접수 후 202 반환                    |
| GET    | `/sources/snapshots`               | 출처별 저장 이력, `limit`·`offset` 페이지 조회                   |
| GET    | `/sources/records`                 | 최신 저장 자료 목록, 출처·CVE 부분검색·패키지·릴리스·기준본 필터 |
| GET    | `/sources/cves/{cve_id}`           | CVE별 출처 자료와 KEV 상태, 연결된 Oracle 공지 주소              |
| GET    | `/sources/documents/{document_id}` | 저장 원문과 출처·해시 조회                                       |

수집 본문은 Ubuntu `{"release":"22.04","package":"apache2"}`, NVD `{"cve_id":"CVE-2023-25690"}`, CISA·Apache `{}`, Oracle `{"url":"https://www.oracle.com/security-alerts/cpujan2024.html"}`입니다. 출처에 맞지 않는 필드와 미지원 대상은 거부합니다.

## 출처 이용 표시

Ubuntu 자료의 저작자와 이용 조건은 [Canonical 저장소](https://github.com/canonical/ubuntu-security-notices)에서 확인할 수 있습니다(CC BY-SA 4.0). 이 프로젝트의 정규화는 원문에서 일부 필드를 추출하는 변환이며 원문과 출처를 함께 보존합니다. CISA 자료는 공식 저장소의 CC0 표시를 따릅니다. 제품 공지와 NVD 자료의 권리는 각 제공자에게 있습니다. NVD 데이터 사용은 NVD나 NIST의 보증·추천을 의미하지 않습니다.
