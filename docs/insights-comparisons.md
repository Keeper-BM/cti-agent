# 취약점 인사이트와 상태 비교

## 취약점 분석과 인사이트

**취약점 분석**은 저장된 설치 정보와 공식 수정 기준을 규칙으로 비교해 판단·이유·근거를 저장합니다. **취약점 인사이트**는 사용자가 선택한 완료 분석을 근거로 질문에 한국어로 답합니다. LLM이 분석 원본을 수정하거나 새 취약 판정을 저장하지 않습니다.

인사이트에서 자산을 선택하고 완료 분석을 최대 5개까지 담은 후 질문합니다. `분석에서 추가 확인이 필요한 이유와 먼저 확인할 사항을 알려줘` 또는 특정 CVE를 지정할 수 있습니다. 결과에는 답변·인용, 제공한 분석 원본·버전, 근거 조각·출처·해시, 생성 시각·모델이 함께 표시됩니다.

## 근거 검색

분석에 고정된 자료 기준본 안에서만 검색합니다. 관련 CVE별 대표 결과 최대 12개를 선정하고 공식 레코드를 문자 조각으로 나눕니다. 조각의 단어·한국어 2글자 토큰을 희소 벡터로 저장하며 TF-IDF 코사인 점수와 정확한 CVE 일치로 최대 10개를 가져옵니다. 소수의 한국어 용어 확장을 사용합니다.

검색 버전은 `local-tfidf/1.1`입니다. 외부 임베딩 API·GPU·모델 다운로드가 필요하지 않으며 신경망 의미 검색과는 검색 특성이 다릅니다. 동의어·질문 표현에 따라 자료를 찾지 못할 수 있습니다. 전체 자산에 대한 포괄적 위험 순위를 산출하지 않습니다.

조각의 시작·끝 위치는 저장된 **정규화 레코드**에서의 문자 위치입니다. 공식 원문의 바이트 위치가 아닙니다. 원문 문서 ID·URL·SHA-256과 정규화 레코드 ID를 함께 저장해 추적합니다.

## 생성·권한·실패

질문·패키지·판단·근거 발췌를 학교 API에 전달합니다. 자산 이름·서버 주소·담당자 필드는 제공하지 않지만, 사용자가 질문에 직접 입력한 내용은 전달됩니다. 학교 API 키는 백엔드에서만 사용합니다.

형식·분석 기준 해시·인용 ID·허용 CVE·일부 위험한 표현을 검사하고 원본 버전·판단은 서버 데이터로 별도 표시합니다. 이 검사는 생성 문장 전체의 사실성을 보장하지 않습니다. 근거가 없는 질문은 `INSUFFICIENT_EVIDENCE`로 표시하며, 검색 결과가 없으면 모델 호출 없이 이유를 저장합니다. 모델 장애·검증 실패 시 오류 작업만 남기고 이전 답변은 유지합니다.

질문의 모든 자산에 접근할 수 있어야 생성·목록·상세·작업 조회가 가능합니다. 권한이 취소된 다중 자산 질문을 일부 자산만 허용된 사용자에게 보여주지 않습니다. Worker는 시작과 저장 시 모든 범위를 다시 확인합니다.

API는 `POST /questions`의 `{"analysis_ids":["UUID"],"question":"질문 내용"}`, `GET /questions`, `GET /questions/{id}`입니다. POST는 Idempotency-Key를 요구합니다. 질문은 공백 제거 후 5~2,000자이며 동일 분석의 중복 선택을 거부합니다. 이력과 답변은 DB에 고정합니다.

## 대응 권고

새 분석 결과마다 공식 수정 기준·출처 확인·실제 적용 조건·조치 후 재수집 절차를 제공합니다. 우선순위는 현재 판단, KEV, 수정 기준과 CVSS를 이용한 **검토 순서**입니다. 긴급 검토는 취약 확정과 다릅니다. 안내는 원본 공식 근거로 연결하고 임의의 완화 명령을 생성·실행하지 않습니다.

## 같은 기준의 전후 비교

완료된 분석의 **전후 비교**에서 같은 자산의 다른 인벤토리를 선택합니다. 같은 OS 릴리스·아키텍처만 비교합니다. 양쪽 입력을 **기준 분석의 동일한 보안 자료**와 현재 규칙으로 다시 평가하므로 자료 갱신에 의한 차이를 패치 효과로 오해하지 않습니다.

ADDED·REMOVED·CHANGED·UNCHANGED를 패키지·아키텍처·CVE별로 저장합니다. 설치·수정 버전, 비교 상태, 최종 판단, 출처 상태와 이유를 확인합니다. 제거·누락은 해결을 의미하지 않으며 부분 수집 입력이면 한계를 표시합니다. 과거 분석은 그대로 보존합니다.

API는 `POST /comparisons`의 `{"baseline_analysis_id":"UUID","target_inventory_id":"UUID"}`, `GET /comparisons`, `GET /comparisons/{id}`입니다. 입력·자료·해시를 요청 시 고정하고 COMPARISON Worker가 처리합니다. Idempotency-Key와 해당 자산의 실행 권한이 필요합니다.

질문 생성 규칙 `scoped-question/1.1`은 형식·인용·숫자 버전 표현 검증 실패에 한해 최대 한 번 같은 근거로 수정 답변을 요청합니다. 수정 답변도 동일 검사를 통과해야 저장합니다. 네트워크·인증·한도 오류는 자동 재시도하지 않으며 토큰 사용량에 두 요청을 합산합니다. 수집 단계의 “아직 자산 판정을 하지 않음” 안내는 이미 완료된 분석의 설명과 혼동하지 않도록 질문 조각에서 제외하며 공식 원문·원본 레코드는 보존합니다.
