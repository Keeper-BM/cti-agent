# CVE AI Summary

취약점 분석 상세에서 학교 LLM API로 한국어 설명을 생성하고 이력으로 저장합니다. 설명은 한 자산의 한 분석·패키지·CVE 결과에 묶입니다. 모델이 자산의 판정을 새로 계산하지 않습니다. 완료 분석 여러 건의 질문·희소 TF-IDF 검색은 별도 취약점 인사이트에서 제공합니다.

## 사용 방법

1. `.env`에 학교 API 주소·키·모델을 설정하고 API와 Worker를 재시작합니다.
2. **취약점 분석**에서 완료된 분석을 선택하고 CVE의 **근거 보기**를 누릅니다.
3. **AI Summary → 요약 생성**을 누릅니다. 대기·생성 중 상태를 거쳐 완료되면 자동 표시됩니다.
4. **취약점 개요**, **패키지 분석 결과**, **권고 조치**를 확인합니다.
5. 문장 옆 `E1` 등의 인용이나 **참조 근거** 버튼으로 원문 발췌·공식 링크·수집 시각을 확인합니다. `A1`은 저장된 분석 자체입니다.
6. **요약 생성 이력**에서 이전 요약을 선택합니다. **요약 재생성**은 새 기록을 추가하며 이전 요약을 덮지 않습니다.

화면 진입·이력 조회·새로고침은 LLM을 호출하지 않습니다. 생성 버튼 또는 POST 요청 때만 호출하며, 같은 Idempotency-Key의 재요청은 기존 작업을 반환합니다. 다른 키의 새 요청은 설명 작업이 대기·실행 중이면 409로 거부합니다. 브라우저를 닫아도 이미 접수한 작업은 Worker가 처리합니다. 비활성 자산의 새 요청은 거부하고 저장된 설명은 유지합니다.

## 설정

```dotenv
LLM_BASE_URL=https://code.cu.ac.kr/llm/v1
LLM_MODEL=Qwen/Qwen3.8-Flash-Next-FP8
LLM_API_KEY=<학교에서 발급한 키를 로컬에 입력>
LLM_TIMEOUT_SECONDS=45
LLM_MAX_TOKENS=2200
```

키는 브라우저·코드·로그·DB에 넣지 않습니다. 백엔드 `SecretStr` 설정에서 읽고 학교 요청의 Authorization 헤더에만 사용합니다. `.env`는 Git에서 제외됩니다. 이미 설정한 키를 채팅에 다시 올릴 필요는 없습니다.

현재는 학교 주소만 허용합니다. 다른 호스트나 경로로 변경하면 생성 요청이 거부됩니다. API·Worker 시작 시 외부 연결은 없으며 설정 누락이 기존 분석·근거 조회를 막지 않습니다. `GET /explanations/status`는 로컬 설정 여부만 반환하며 인증 유효성·모델 가동 상태를 미리 보장하지 않습니다. Compose의 API·Worker에도 같은 환경변수가 전달됩니다.

[학교 API 안내](https://bootcamp.cu.ac.kr/notices/b1869f20-a5f7-47a3-8d96-9c00900abdcd)의 chat completions 방식을 사용합니다. 생성 요청은 JSON 출력 형식과 비스트리밍 응답을 요청합니다. Qwen 모델의 `enable_thinking: false` 옵션으로 최종 설명을 직접 요청하며, 내부 추론 응답은 저장하지 않습니다. [Qwen 공식 모델 문서](https://huggingface.co/Qwen/Qwen3.8-Flash-Next-FP8).

## 무엇을 전달하는가

모델에는 다음만 전달합니다.

- 해당 CVE, Ubuntu 릴리스, 패키지 이름과 설치·수정 버전
- 저장된 최종 판단, 버전 비교 결과, 출처 확인 상태, KEV 상태, 가상 여부
- 저장된 판단 이유·추가 확인 사항
- **그 분석 당시** 사용한 공식 자료의 발췌와 임시 인용 ID

자산 이름·호스트/IP·담당자·SSH 정보·DB 식별자는 요청 본문에 포함하지 않습니다. 외부 문서는 지시가 아닌 참고 자료로 취급하도록 시스템 프롬프트에 명시합니다. 자동 웹 검색, 실행 도구, 명령 실행 권한은 제공하지 않습니다.

출처별 대표 기록을 먼저 고른 뒤 최대 8개의 공식 기록을 전달하며 각 기록은 최대 5,000자입니다. 일부만 사용했으면 화면에 한계를 표시합니다. 소스·릴리스가 다른 Ubuntu 기록을 이 패키지의 판정 근거로 넣지 않습니다. 요청 시 근거 발췌·문서 ID·해시를 고정하므로 이후 수집·분석·모델 설정 변경이 이전 설명을 바꾸지 않습니다.

## 화면의 원본과 AI 작성 구분

**취약점 개요**와 **권고 조치**는 AI가 작성합니다. **패키지 분석 결과**의 판단·버전·판단 이유는 백엔드가 저장된 분석에서 가져와 구성합니다. JSON 출처 미검증, 설정 미확인, 가상 입력 표시도 원본에서 유지합니다.

생성 결과는 다음 검사를 거칩니다.

- 엄격한 JSON 구조·길이·타입 검사. 추가 필드, 중복 키, NaN, 잘린 응답 등 거부
- 모델이 반환한 기준값 전체가 저장 입력과 같은지 비교
- 의미 설명에 공식 근거 ID가 있고 다음 확인 사항에 분석 근거 ID가 있는지 확인
- 모든 인용 ID의 존재·중복 검사. URL은 모델이 만든 값 대신 저장된 공식 메타데이터 사용
- 한국어 포함 여부와 임의 URL·버전 숫자·HTML·다른 CVE·비밀키 형태·일부 명백한 자산 상태 단정 표현 거부
- 실제 API 응답 모델이 요청한 모델과 다른 경우 거부

이 검사는 **문장의 의미가 근거와 완전히 일치한다는 증명은 아닙니다.** 모델이 올바른 ID를 인용하고도 부정확한 설명을 할 수 있습니다. 화면은 ‘AI 작성’과 ‘저장된 원본’을 구분하고 인용·기준값 검사 범위를 표시합니다. 공식 조건과 원문을 함께 확인해야 합니다. 정규식으로 모든 모순·환각을 차단했다고 주장하지 않습니다.

## 오류와 저장

`EXPLANATION` 작업과 `explanations` 테이블을 추가한 `0005` 마이그레이션을 사용합니다. 테이블에는 분석·결과 ID, 요청 모델, 서버 응답 모델, 프롬프트 버전, 고정 입력·SHA-256, 검증된 출력, 토큰 사용량과 생성 시각을 저장합니다. API 키·내부 추론·검증 실패 응답 원문은 저장하지 않습니다.

전체 입력 최대 90,000바이트, 응답 최대 256 KiB, 설명 JSON 최대 24,000바이트를 제한합니다. 기본 총 대기 시간은 45초이며 5~60초로 설정 가능합니다. 출력 토큰 제한은 기본 2,200, 허용 512~4,096입니다. TLS 인증서를 검증하고 리디렉션·자동 재시도를 사용하지 않습니다. 동일 DB에서는 대기·실행 중인 설명 한 건만 허용하도록 고유 슬롯을 둡니다.

인증 실패, 사용량 제한, 연결 실패·시간 초과, 형식·인용·기준값 오류를 구분해 표시합니다. 실패한 설명은 결과를 공개하지 않고 이전 성공 설명과 분석을 유지합니다. 결과와 작업 성공 상태는 같은 트랜잭션으로 저장합니다. Worker 중단 후 미완료 작업은 실패 처리하며 자동 재호출하지 않습니다. 새 요청으로 다시 생성할 수 있습니다.

## API

모든 경로는 `/api/v1` 기준이며 개발용 토큰이 필요합니다.

| 메서드 | 경로                            | 동작                                                           |
| ------ | ------------------------------- | -------------------------------------------------------------- |
| GET    | `/explanations/status`          | 키를 제외한 설정 여부·모델 표시. 외부 요청 없음                |
| POST   | `/explanations`                 | `{"finding_id":"UUID"}`, `Idempotency-Key` 필수. 202 작업 접수 |
| GET    | `/explanations?finding_id=UUID` | 해당 결과의 생성 이력. `limit` 1~50, 기본 10; `offset` 0 이상  |
| GET    | `/explanations/{id}`            | 작업 상태·검증된 설명·인용·모델·생성 시각 조회                 |

`capabilities.features.ai_explanations=true`는 구현 여부입니다. 실제 사용 가능 여부는 설정과 학교 API 상태에 따라 다릅니다. `rag`와 선택 분석 질문 `/questions`도 구현했으며 구체적인 범위는 인사이트 안내를 따릅니다.

[실제 검증 화면](screenshots-ai-explanation.jpg), [검증 기록](verification.md).

선택한 완료 분석에 대한 자유 질문과 근거 검색도 별도 **취약점 인사이트** 화면으로 제공합니다. [범위와 검색 방식](insights-comparisons.md).
