# 실제 ‘영향 있음’ 시연 — Apache CVE-2024-27316

2026-11-11, 사용자 요청에 따라 기존 VirtualBox의 **CTI Ubuntu VM**에 Ubuntu 공식 초기 Apache 패키지를 실제 설치하고 재수집·검증·분석했습니다. 가상 CVE나 수동으로 바꾼 판정값이 아닙니다.

## 현재 시험 상태

| 항목           | 내용                                                                      |
| -------------- | ------------------------------------------------------------------------- |
| OS             | Ubuntu 24.04 amd64                                                        |
| 설치한 Apache  | `2.4.58-1ubuntu8` (apache2, apache2-bin, apache2-data, apache2-utils)     |
| 공식 수정 기준 | `2.4.58-1ubuntu8.1`                                                       |
| 대상 CVE       | CVE-2024-27316                                                            |
| 확정한 행      | apache2-bin / 영향 있음(AFFECTED)                                         |
| 서비스         | VM 내부 `127.0.0.1:80`, HTTP/2 h2c 활성                                   |
| 네트워크       | VirtualBox NAT, Windows 루프백 2222의 SSH만 포워딩; HTTP 외부 포워딩 없음 |
| 버전 유지      | 시연 중 자동 갱신 방지를 위해 Apache 4개 패키지만 apt hold                |

MySQL과 Windows 가상화 설정은 변경하지 않았습니다. Apache 서비스만 재시작했으며 VM·Windows는 재부팅하지 않았습니다.

## 실제 판정 근거

[Ubuntu CVE 자료](https://ubuntu.com/security/CVE-2024-27316)는 Ubuntu 24.04의 수정 기준을 제공합니다. [Apache 공식 공지](https://httpd.apache.org/security/vulnerabilities_24.html#CVE-2024-27316)는 HTTP/2 처리의 메모리 고갈 문제와 영향 범위를 설명합니다. [mod_http2 문서](https://httpd.apache.org/docs/2.4/mod/mod_http2.html)는 모듈과 프로토콜 활성 조건을 설명합니다.

`ubuntu-packages/1.2`는 다음 조건을 모두 만족한 **이 한 가지 릴리스·버전·CVE·바이너리 사례**만 확정합니다.

1. Ubuntu 자료가 같은 CVE·apache2·24.04의 수정 기준 `2.4.58-1ubuntu8.1`과 영향 버전 `2.4.58-1ubuntu8`을 명시합니다.
2. 실제 SSH 인벤토리이고, 공식 Ubuntu 서명·패키지 해시·설치 파일 검증이 일치합니다.
3. root 소유의 고정 관측기가 Apache 서비스 PID·실행 파일·메모리에 매핑된 mod_http2 파일의 inode와 해시를 확인합니다.
4. 같은 프로세스가 `127.0.0.1:80` 리스너를 소유하고, **정상 HEAD 요청 한 번**에 HTTP/2 200으로 응답합니다.
5. 관측 전후 PID·시작 시각·파일이 바뀌지 않았고, 관측 결과가 같은 검증 ID·패키지 버전에 연결됩니다.

원격 관측기는 임의 명령·주소·입력을 받지 않습니다. `/usr/bin/python3 -I /usr/local/libexec/cti-apache-observer.py`만 제한적으로 sudo 허용하며, 수집 계정의 일반 sudo 명령은 거절되는 것을 확인했습니다. 서버에 관측기가 없거나 해시·권한·조건을 확인하지 못하면 기존 파일 검증은 유지하고 해당 CVE는 추가 확인으로 남습니다. JSON·CSV로 실행 근거나 검증 ID를 입력해 신뢰 상태를 올릴 수 없습니다.

이는 공식 취약 버전과 적용 가능한 로컬 서비스 조건의 확인입니다. 서비스 거부 공격·메모리 고갈·서버 중단을 실행하지 않았으며 외부 공격 가능성·서버 전체 상태를 증명하지 않습니다. 다른 CVE나 일반 Apache 환경에 이 조건을 확대 적용하지 않습니다. 같은 소스에 속한 apache2·apache2-data·apache2-utils 행도 자동 확정하지 않습니다.

## 교수님께 보여드릴 순서

1. 웹에서 **취약점 분석 → CTI Ubuntu VM**을 선택합니다.
2. 최신 분석 **`826d87d0`**을 선택합니다. 전체 결과의 첫 행이 **apache2-bin / CVE-2024-27316 / 영향 있음**입니다.
3. **근거 보기**에서 설치 버전·공식 수정 기준·판단 이유와 **실행 조건 확인 · Apache HTTP/2**를 보여줍니다.
4. “공식 취약 버전의 파일과 실제 HTTP/2 활성 조건을 확인한 결과입니다. 공격을 실행하거나 판정을 수동으로 넣은 것이 아닙니다.”라고 설명합니다.
5. 대응 권고에서 공식 수정 패키지 검토와 조치 후 재수집 절차를 확인합니다. 저장된 학교 API 설명 `c51391aa`도 보여줄 수 있습니다.
6. 취약점 인사이트에서 같은 분석을 선택하고 저장된 질문 `91173cec`의 답변·원본 표·인용을 보여줍니다. 질문은 “CVE-2024-27316의 저장된 영향 판정과 근거, 우선 확인할 대응 절차를 설명해줘.”입니다.
7. 이전 수정 버전 분석과 현재 분석을 비교하고, 보고서를 다운로드합니다. 실제 재수집부터 진행하는 순서는 [전체 시연 순서](demo-guide.md)를 따릅니다.

| 확인 단계                  | 저장 분석 ID                           | 기대·실제 결과 |
| -------------------------- | -------------------------------------- | -------------- |
| 수정된 버전 + HTTP/2       | `de0a4cdf-ee4b-49d3-bf7a-0373e9fc3e60` | FIXED          |
| 취약 버전 + HTTP/2 모듈 끔 | `2be8b3d7-e27e-4a56-a5fe-4ad70e16030e` | NEEDS_REVIEW   |

전후 비교 `ef4210eb-c6b8-4991-b520-1344b53194e7`, 기본 보고서 `70e4b99d-198f-472f-86f6-0161a33fa957`, AI 설명 포함 보고서 `c3635d9b-2d96-43e2-bec0-0cfc28e96f46`을 저장했습니다. 기본 파일은 `D:\CTI-Ubuntu\실제-영향있음-CVE-2024-27316-보고서.md`, AI 포함 파일은 `D:\CTI-Ubuntu\실제-영향있음-AI포함-보고서.md`입니다. 두 파일 모두 다운로드 본문과 저장된 SHA-256이 일치했습니다.

학교 API 질문·CVE 설명은 실제 요청으로 성공했습니다. 새로운 실행 조건 화면은 TypeScript·빌드를 통과했으나, 브라우저 제어 도구 초기화 오류로 직접 클릭·레이아웃은 확인하지 못했습니다. 원복 스크립트는 아래 설명대로 준비만 했습니다.

## 원복

현재 VM은 **의도적으로 취약 버전을 설치한 로컬 시연 상태**로 남겨 둡니다. 다음 파일은 시연이 끝난 뒤에만 실행하세요. 이 스크립트는 아직 실제 실행하지 않았으며, 실행하면 Apache의 hold를 해제하고 저장소의 수정 버전으로 업데이트한 뒤 시연 HTTP/2 설정을 끕니다. 루프백 바인딩과 분석·보고서 이력은 유지합니다.

```powershell
& 'D:\cti-agent-runtime\venv\Scripts\python.exe' 'D:\CTI-Ubuntu\restore-apache-after-demo.py' --restore
```

원복 후 새 수집 → 공식 파일 검증 → 새 분석으로 FIXED를 확인합니다. 과거 AFFECTED 보고서는 당시 기록으로 남습니다.

VM의 설정까지 완전히 이전으로 돌아가려면 VirtualBox에서 VM을 정상 종료한 뒤 스냅샷 `pre-cve-2024-27316-20261111`을 복원합니다. 이는 VM 내부를 스냅샷 시점으로 되돌리므로 그 이후 VM 변경도 함께 되돌아갑니다. Windows의 CTI DB·보고서는 별도 보존돼 있습니다.

VM 스냅샷 UUID `b1090d84-2f1a-44f5-85a0-53f055553540`, 변경 전 앱 DB 백업 `D:\cti-agent-runtime\before-affected-lab-20261111013518.db`. VM 내부 Apache 설정 백업은 `/var/lib/cti-lab/cve-2024-27316/apache-config-before.tar.gz`입니다.
