# 검증 기록

## Compose → 실제 VM SSH·PostgreSQL·화면 통합 — 2026-11-12 KST

별도 Docker 프로젝트에서 Nginx → API → PostgreSQL → Worker → 실제 Ubuntu 22.04 VM
경로로 패키지 642개와 Apache·MySQL 활성 상태를 수집했습니다. 실제 브라우저 수집 버튼과
서비스 상태·패키지 조회도 확인했습니다. 정상·부분 수집, 호스트 키 오류·허가 대상·키 권한
거부, 볼륨 보존 재기동 후 응답 일치를 검증했습니다.

실제 Compose Worker를 수집 중 SIGKILL한 뒤 `WORKER_RESTARTED` 실패 처리,
감사 이벤트 1건, 이전 스냅샷 보존과 새 수집 성공을 확인했습니다.
재실행 가능한 `scripts/smoke_ssh_http.py`와 보호 조건 단위 시험 3개를 추가했습니다.

PR의 첫 원격 CI에서는 Backend·Frontend 통과, Compose IP 점유 단계 실패를 확인했습니다.
CI 전용 명시적 서브넷과 stderr 보존으로 보완했습니다. 동일 구성의 로컬 검사와
수정 커밋 `dd6bf9b`의 [원격 CI #10](https://github.com/Keeper-BM/cti-agent/actions/runs/43142429093)에서
Backend·Frontend·Compose 세 작업이 모두 통과했습니다.
최신 원격 결과는 [PR #1](https://github.com/Keeper-BM/cti-agent/pull/1)의 커밋별 CI를 참조하세요.
실제 실행 범위·재실행 방법은 [Compose SSH 통합 검증](compose-ssh-verification.md)에 있습니다.

## PostgreSQL 기능 매트릭스·최종 회귀 — 2026-11-11 KST

자산·CSV/JSON 입력·계정 권한·SSH 수집·Worker 복구의 기존 시험 67개를
PostgreSQL에서도 실행하도록 `--postgres-matrix`를 추가했습니다. 시험마다 별도 DB를
생성·마이그레이션·정리하며 SQLite 전용 백업 검사는 기존 실행을 유지합니다.
기존 기대값을 재사용하고 CI의 백엔드 검사에도 매트릭스를 연결했습니다.

실제 Ubuntu 22.04의 Apache·MySQL과 전용 PostgreSQL 17.11·pgvector 0.8.7을 사용한
최종 전체 결과는 **398 passed, 0 skipped / 74.11초**입니다. 경고는 기존 TestClient
deprecation과 JUnit `record_property` 형식 안내 각 1건입니다. Ruff 173개 파일과
Compose·CI YAML 검사도 통과했습니다. 마지막 프론트엔드 검사는 8개 통과·타입·빌드·포맷
통과이며 이후 화면 코드를 바꾸지 않았습니다.

Compose 최종 논리 백업도 별도 DB에 복원해 24개 테이블의 행 수·내용 해시를 대조했습니다.
추가 PostgreSQL 시험 DB의 잔여 수가 0임을 확인하고 시험 전용 컨테이너·볼륨을 제거했습니다.
실행 방법과 검증 경계는 [PostgreSQL 시험 안내](postgres-testing.md)를 참조하세요.

## Compose 전체 기동·계정·API 주소 변경 복구 — 2026-11-11 KST

별도 Docker 프로젝트에서 전체 이미지 빌드, DB 마이그레이션, 웹 → API → DB → Worker
작업 완료와 볼륨 보존 재기동을 확인했습니다. 재기동 전후 자산·완료 작업 응답이 같았습니다.
계정 모드 전환 중 API IP가 변경되어 Nginx가 502를 반환하는 결함을 발견해
런타임 Docker DNS 조회로 수정했습니다. 이전 IP를 별도 컨테이너로 점유시킨 회귀 검사에서
Web 재시작 없이 새 API 주소로 복구했습니다. CI에도 해당 검사를 추가했습니다.

실제 웹 프록시에서 계정 로그인·쿠키·CSRF·Origin 검증·로그아웃·인증 실패 429를
확인했습니다. Web healthcheck도 프록시 준비 상태를 확인하도록 추가했습니다.
실행 범위·근거·재현 절차는 [Compose 배포 검증](compose-verification.md)에 있습니다.

과거 근거는 서비스 미수집 상태로 읽으며 판정 엔진의 확정 조건에는 사용하지 않습니다.
명령 제한 래퍼 생성 도구와 선택적 파일 검사 허용도 추가했습니다.

초기 전체 Python 329개 통과 후, Worker 복구 감사와 실제 프로세스 종료·재시작 시험을

통과. Ubuntu 24.04와 새 22.04 VM에서 실제 MySQL 수집·CTI DB 복원을 확인했고,
22.04에 Apache도 설치해 두 서비스의 활성 상태와 패키지 642개를 함께 수집했습니다.
Vite → 별도 API/Worker → SSH 경로와 실제 브라우저에서 서비스 활성/중지·유닛 부재
표시도 확인했습니다. 범위와 원시 증거는 [서비스 수집 검증 기록](service-collection-verification.md)에 있습니다.

## 화면·보고서 용어 정리 — 2026-11-11 KST

사용자 요청에 따라 대화체 제목·버튼·보조 문구를 제품 화면 용어로 정리했습니다. AI 설명 패널은 **AI Summary**, 세부 항목은 **취약점 개요 / 패키지 분석 결과 / 권고 조치 / 참조 근거**로 통일했습니다. 인사이트는 **AI Q&A / 질의 실행 / AI Response**, 나머지 화면은 **보고서 생성 / 대응 권고 / SSH 패키지 수집 / 분석 전후 비교** 등으로 정리했습니다. AI 생성 표시와 분석 원본의 구분, 검증 범위·제한 사항은 유지합니다.

- TypeScript·Vite 빌드, Ruff 검사·포맷, 기존 보고서 통합·Markdown 시험 15개를 통과했습니다. 문구 변경에 따라 기존 시험의 표기 기대값만 갱신했습니다.
- 브라우저 제어가 이번에는 정상 동작해 실제 로그인된 웹의 CVE-2024-27316 상세에서 AI Summary와 새 세부 제목을 확인했습니다. 질문 이력의 AI Response, 보고서 생성 옵션·이력·AI 포함 미리보기도 직접 확인했습니다.
- 새 Markdown 양식은 `assessment-report/1.2`입니다. 실제 분석 `826d87d0`의 새 보고서 `31555916-fe58-4eec-a362-7fb6cc94a1a6` 생성·다운로드와 SHA-256 일치를 확인했습니다. 기존 보고서 `c3635d9b`의 파일 해시는 유지됐습니다.
- 새 파일: `D:\CTI-Ubuntu\실제-영향있음-보고서-새양식.md`. 결과 SHA-256: `f1c9fa2b5554a26d5ac676e02496efa77c16546e05ff992db128eeb5d558cf00`.

이번 작업은 표시 문구와 새 보고서 양식 변경입니다. 분석 판정·근거·LLM 프롬프트·저장된 생성 문장은 변경하지 않았으며 학교 API를 추가 호출하지 않았습니다. 아래 브라우저 미검증 기록은 각 작업 당시의 결과이고, 이번 확인은 위 화면 범위에 한정됩니다.

`ubuntu-packages/1.2`의 새 확정 조건은 이 CVE·Ubuntu 24.04 amd64·초기 Apache 버전의 apache2-bin에만 적용합니다. `ubuntu-files/1.1`은 선택적 고정 관측기의 해시·소유권을 확인하고, 관측 결과를 검증 ID·패키지 버전에 연결합니다. 관측기 없음·모듈 비활성·다른 버전·공식 파일 불일치·시간/검증 ID 불일치·다른 CVE는 이 경로로 확정하지 않습니다. JSON·CSV에 실행 근거나 검증 ID를 넣어 신뢰를 높이는 입력도 거절합니다. 질문의 CVE 대표 행 선택은 AFFECTED를 우선하며 해당 회귀시험을 포함했습니다.

공격·메모리 고갈 시험은 수행하지 않았습니다. 실제 루프백 서비스 조건의 확인이며 외부 공격 가능성이나 서버 전체 보안 상태를 증명하지 않습니다. 새 실행 조건 화면의 직접 클릭·레이아웃은 도구 초기화 오류로 시험하지 못했습니다. 시연 후 업데이트용 원복 스크립트는 준비만 했으며 실행하지 않았습니다. 현재 취약 버전 네 패키지를 hold한 채 서비스·웹·Worker를 유지하고 있습니다. VM·Windows 재부팅, WSL, 가상화 설정 변경은 없었습니다.

시연·원복 절차와 공식 출처는 [실제 영향 있음 시연](affected-demo.md), 현재 네 단계 흐름은 [교수님 시연 순서](demo-guide.md)를 참조하세요. 자세한 시험 결과 XML은 `D:\cti-agent-runtime\affected-lab-final-tests.xml`에 있습니다.

## 전체 결과의 판단 우선 정렬 — 2026-11-11 KST

사용자 리허설에서 발견한 ‘지원 범위 밖’ 결과의 상단 노출을 개선했습니다. `/findings`는 페이지를 나누기 전에 영향 있음 → 추가 확인 필요 → 수정 기준 충족 → 영향 없음 → 수집 실패 → 설치 여부 미확인 → 대조 자료 없음 → 입력 목록에 없음 → 지원 범위 밖 순으로 정렬합니다. 같은 상태는 CVE·패키지 이름·결과 ID로 정렬하며 화면의 필터 선택지도 같은 순서로 표시합니다.

관련 분석·권한 통합시험 11개, Ruff 검사·포맷, TypeScript·Vite 빌드를 통과했습니다. 혼합된 판단·처리 상태, 동률, 페이지 경계, 검색·상태 필터와 저장 결과 보존을 확인했습니다. 실행 중인 API에 적용한 뒤 실제 Vite 프록시에서 분석 `c994efa4`의 첫 페이지가 NEEDS_REVIEW이고, 그 348건 다음은 FIXED, 1,699건 다음부터 마지막까지는 OUT_OF_SCOPE임을 확인했습니다. 전체 2,378건과 검색·필터 결과는 유지됐습니다. 이번 정렬 변경 후 실제 브라우저 클릭·레이아웃은 별도 검증하지 않았습니다.

### 실패 원인과 수정

- 참고용 APT 캐시 조회가 길어져 필수 패키지 수집 전체가 실패하던 경우를 보완했습니다. 고정 12초 제한을 적용하고 참고 조회 실패는 필수 목록과 분리합니다. SSH 전체 제한은 60초이며 부하가 낮아진 실제 재시연에서는 전체 성공했습니다.
- 학교 모델이 Ubuntu/MySQL 버전 숫자를 문장에 넣어 QUESTION_TEXT_INVALID로 거절되던 문제를 확인했습니다. 정확한 숫자는 원본 표에 두고 프롬프트를 보완했으며, 형식 검사 실패에만 한 번 수정 요청합니다. 검증 조건은 완화하지 않았습니다. 수정 후 broad 질문과 특정 CVE 질문이 실제 학교 API로 성공했습니다.
- 수집 단계의 “자산 분석 미실행” 안내가 완료 분석 답변과 혼동되는 것을 발견해 검색 문맥에서 구분하고 모순 표현을 거절합니다. 기존 원문·레코드·이력은 유지합니다.
- Vite·Nginx의 Host 포트 보존 문제를 수정해 정상 계정 요청의 CSRF 거절을 방지했습니다.

잘못된 인용·모델 한도 실패·근거 부족·다중 자산 권한 회수·원본 변조·Worker 중단을 자동시험으로 확인했습니다. 의미 전체의 사실성·모든 질문의 성공을 보장하지 않습니다. Starlette TestClient의 httpx deprecation 경고 1종은 남아 있으며 시험 실패는 아닙니다.

## 미검증 범위

- Docker CLI·런타임이 없는 로컬 환경에서 검사했으므로 Compose 이미지 빌드·전체 기동은 미검증입니다.
- PostgreSQL·pgvector 전용 테스트 1건은 로컬에서 건너뛰었습니다. 별도의 시험용 DB로 실행해야 합니다.
- GitHub Actions 설정은 존재하지만 원격 실행 결과는 기록되지 않았습니다.
- 실제 Ubuntu 수집, 공식 CVE 판정, GPU 모델, RAG, 계정 인증과 보고서는 구현·인수 시험 대상입니다.

## 자동화 검사 재현

```bash
uv run ruff check backend scripts tests
uv run ruff format --check backend scripts tests
uv run pytest
npm --prefix frontend run format:check
npm --prefix frontend test
npm --prefix frontend run build
```

PostgreSQL 전용 검사는 `TEST_POSTGRES_URL`에 별도의 시험용 PostgreSQL·pgvector DB를 지정하여 실행합니다. 이 테스트는 마이그레이션과 작업 처리를 수행하므로 애플리케이션 데이터가 있는 DB와 분리합니다.

```bash
uv run pytest tests/integration/test_postgres.py
```

## HTTP 연동 검사

API·Worker·웹이 실행된 상태에서 다음 중 해당 실행 방식의 명령을 사용합니다. 연결 확인 작업 한 건이 생성됩니다.

```bash
# Compose 기본 웹 포트
uv run python scripts/smoke_http.py

# 로컬 API·Worker·Vite
SMOKE_BASE_URL=http://127.0.0.1:5173 uv run python scripts/smoke_http.py
```

브라우저 시험에는 문서용 주소를 사용했으며 해당 주소로 서버 연결을 수행하지 않았습니다. 로컬 시험 DB와 화면 캡처는 `.data/`에 저장되며 Git 업로드 대상이 아닙니다.
