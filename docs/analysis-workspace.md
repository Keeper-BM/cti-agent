# 분석 워크스페이스

시연을 시작할 화면은 `/#/workspace`입니다. 개발 실행기에서 기본 서버와 함께 띄울 경우 저장소에 별도 데이터베이스를 설정하고 `python scripts/dev.py --api-port 8011 --web-port 5174`를 실행합니다. 수동 실행 시 마이그레이션 `alembic upgrade head`와 Worker가 필요합니다.

1. **자산 등록**에서 이름과 예상 OS를 입력한 후 **저장하고 SSH 설정**을 누릅니다. SSH 접속 정보와 호스트 키 지문을 저장하고 **SSH 연결 확인**을 누르면 인증과 패키지 목록 조회를 확인합니다. 인증키와 허용 주소는 서버 측에서 설정합니다.
2. **분석 실행**에서 자산 한 대를 선택하면 SSH로 새로 수집하거나 저장된 패키지 기록을 사용할 수 있습니다. 여러 대를 선택한 후 **일괄 분석 실행**을 누르면 선택한 자산을 SSH로 수집하고 통합 보고서를 생성합니다. SSH 모드는 지원 패키지의 공식 파일도 대조합니다.
3. **집중 보기**를 켜면 발표 화면에서 단계와 핵심 수치를 크게 볼 수 있습니다. 진행 중인 분석은 저장된 단계 상태에 맞춰 이동합니다. 완료된 실행의 **기록 재생**은 저장 시각과 결과를 바탕으로 단계별 화면을 보여 줍니다. **일시 정지**, **이전**, **다음 단계**로 설명 속도를 조절하고 마지막 단계에서 **결과 보기**를 누릅니다. 동작 줄이기 설정에서는 수동으로 단계를 넘깁니다.
4. **분석 결과**에서 영향이 확인된 패키지의 CVE, 설치 버전, 공식 수정 기준과 첫 권고 조치를 확인합니다. 숫자는 패키지·CVE 조합 수입니다. **CVE별 판정**에서는 같은 판정의 CVE를 한 줄로 묶고, **근거 보기**를 펼치면 패키지별 기록을 확인할 수 있습니다.
5. **이 분석에 질문**에서 해당 분석만 대상으로 질문하고, 같은 분석의 이전 답변을 확인합니다. 여러 분석을 함께 선택하려면 메뉴의 **AI 질문**을 사용합니다. **대응 보고서 보기**에서 저장된 문서를 확인하고 **Markdown 다운로드**를 누릅니다. **최근 분석**이나 **분석 이력**에서 다른 기록을 선택하면 단계·자료·결과·보고서가 함께 바뀝니다. 자동 실행 도입 전의 개별 분석에는 저장된 기준본과 결과를 표시합니다. 최근 실행이 중단된 경우 **마지막 정상 분석 보기**에서 저장된 완료 기록을 열 수 있습니다.
6. 일괄 실행 결과에서는 평가 결과가 있는 자산, 미평가, 분석 실패와 고유 CVE 수를 확인합니다. **같은 CVE 비교**에는 자산별 설치 버전, Ubuntu 수정 기준과 판정이 나옵니다. **근거 보기**는 그 패키지의 저장 근거를 엽니다. 통합 파일 생성이 실패하면 **통합 보고서 다시 생성**으로 저장된 판정을 사용합니다.

## 분석 예약

**분석 예약 → 새 예약**에서 SSH가 설정된 활성 자산(1~20대)과 매일 또는 매주 실행할 시각(KST)을 선택합니다. 예약을 저장하면 Worker가 다음 예정 시각부터 SSH 패키지 수집, 공식 보안 자료 갱신, 판정, 보고서 생성을 실행합니다. 브라우저를 닫아도 Worker가 실행 중이면 처리됩니다. Worker를 재시작하면 가장 최근에 놓친 한 회차를 처리합니다. 이전 회차가 아직 진행 중이면 이번 회차의 건너뜀 사유를 기록합니다.

**실행 이력**에서 실행별 결과와 통합 보고서를 엽니다. 각 자산의 첫 정상 회차를 기준으로 삼고, 이후에는 같은 예약의 직전 비교 가능한 결과와 자산·패키지·아키텍처·CVE별 판정 변화를 비교합니다. 수집이 불완전하거나 필수 Ubuntu 자료 갱신에 실패한 결과는 비교 보류로 표시합니다. 이전에 영향이 확인된 항목은 이번 판정이 공식 수정 기준을 충족할 때 수정 확인으로 집계합니다. 근거를 추가로 확인해야 하는 항목은 재확인으로 표시합니다.

## 자료와 판정 범위

- 지원 범위는 Ubuntu 22.04·24.04의 Apache2와 MySQL입니다. 실행마다 설치된 대상 소스 패키지별 Ubuntu CVE와 CISA KEV를 갱신하고, Apache가 있으면 Apache HTTP Server 공지도 갱신합니다.
- NVD는 Ubuntu 결과 중 KEV 등재 건을 우선해 CVE 번호순 최대 3건을 보충 조회합니다. MySQL은 해당 Ubuntu 레코드에 연결된 허용된 Oracle 공지 중 최대 2건을 보충 조회합니다. 공식 보안 자료에는 출처 수와 조회 요청 수를 따로 표시합니다. 요청별 갱신·저장본 사용·실패 상태와 자료 시각을 확인할 수 있습니다.
- 갱신 실패 시 같은 출처·범위의 성공 저장본을 사용하고 기준 시각을 결과 상단에 표시합니다. 필수 Ubuntu 기준본을 확보하지 못한 경우 자료 단계에서 중단합니다. 수집과 공식 파일 대조 사이에 패키지가 변경된 경우 재실행이 필요합니다.
- 통합 결과의 **우선 대응**은 영향 있음, KEV 등재, 확인된 CVSS 점수 내림차순을 적용합니다. 같은 우선순위는 CVE 번호로 정렬합니다. 자산별 평가 건수는 패키지·CVE 조합이며, 통합 상단의 CVE 수는 중복을 제거한 값입니다.
- 보고서는 이번 분석의 규칙 기반 판정과 첫 권고 조치를 상단에 표시합니다. 자동 보고서와 **AI Summary 포함**을 선택한 수동 보고서는 영향 있음 또는 추가 확인 필요 중 대표 판정의 저장 요약을 재사용합니다. 대표 판정에 요약이 없으면 BAZE로 한 건을 생성합니다. 생성에 실패하면 상태 안내와 함께 판정 근거가 담긴 보고서를 저장합니다. AI 질문은 사용자가 선택해 실행합니다. **저장된 답변 보기**에서 이미 생성된 AI 응답을 열 수 있습니다. 파일 대조를 완료하지 못했거나 적용 조건을 입증하지 못한 항목은 검증 한계를 유지합니다.
- 동시에 같은 자산에 한 번만 실행할 수 있습니다. 관리자 또는 해당 자산에 권한이 있는 담당자가 실행할 수 있으며, 조회자는 결과 조회와 다운로드가 가능합니다.

## API

- `POST /api/v1/assets/{asset_id}/ssh-profile/{profile_id}/check` — 호스트 키·SSH 인증·설치 패키지 목록 조회 확인
- `POST /api/v1/assets/{asset_id}/workflows` — `Idempotency-Key` 헤더와 빈 JSON 객체로 SSH 실행, 또는 `inventory_id`로 저장 기록 지정
- `GET /api/v1/assets/{asset_id}/workspace` — 연결 확인 시각과 최근 이력. 선택 매개변수 `analysis_id`로 해당 자산의 완료된 분석·자동 실행·보고서를 함께 조회
- `GET /api/v1/assets/{asset_id}/workflows/{run_id}` — 재접속·개별 실행 조회
- `GET /api/v1/analyses/{analysis_id}/finding-groups?verdict=NEEDS_REVIEW` — 판정별 CVE 목록과 관련 패키지 수. `/findings`의 `analysis_id`, `verdict`, `cve_id`로 정확히 일치하는 패키지 근거 조회
- `GET /api/v1/questions?analysis_id={analysis_id}` — 선택한 분석 하나를 대상으로 한 질문 이력. `answered=true`로 완료된 AI 답변만 조회
- `GET /api/v1/workflow-batches/{batch_id}/comparison?cve_id=...` — 일괄 실행에 고정된 서버별 판정 비교
- `POST /api/v1/workflow-batches/{batch_id}/report/retry` — 저장된 분석을 사용해 통합 보고서 재생성 요청
