# 교수님 시연 순서

현재 VM은 실제 취약 Apache 버전과 HTTP/2를 켜 둔 시연 상태입니다. 아래 순서는 **CVE-2024-27316의 영향 있음** 사례를 기준으로 합니다. 구성·판정 범위와 시연 후 원복은 [실제 영향 있음 시연](affected-demo.md)을 확인하세요. 이전 수정 기준 충족 분석·보고서도 보존돼 있습니다.

현재 PC의 웹 주소는 **http://127.0.0.1:5173** 입니다. 계정은 `admin`, 초기 비밀번호는 `D:\CTI-Ubuntu\private\web-password.txt` 파일에서 확인합니다. 비밀번호·학교 API 키·SSH 키는 발표 화면이나 자료에 넣지 않습니다.

2026-11-11에 실제 Vite → FastAPI → SQLite → 별도 Worker → Ubuntu SSH → 학교 API → 보고서 다운로드를 끝까지 시험했습니다. 이전 수정 버전 사례는 사용자와 화면 리허설도 완료했습니다. 이번 영향 있음 사례의 새 실행 조건 화면은 도구 초기화 오류로 브라우저 클릭·레이아웃을 직접 검증하지 못했습니다.

## 시연 전 준비

1. VirtualBox에서 `CTI-Ubuntu`가 실행 중인지 확인합니다. 가상 디스크는 D 드라이브에 있습니다. WSL은 사용하지 않습니다.
2. 웹에 로그인하고 **작업 내역 → Worker 연결 확인**을 눌러 완료되는지 확인합니다. 현재 API·웹·Worker는 실행해 두었습니다.
3. **보안 자료**에서 Ubuntu 24.04의 apache2와 mysql-8.0 자료가 저장돼 있는지 확인합니다. 현재 Ubuntu·KEV·Apache·NVD·Oracle 저장본이 있습니다. 외부 자료 수집은 발표 전에 해두고, 필요할 때 Ubuntu 가져오기 동작을 보여줍니다.
4. **자산 현황 → CTI Ubuntu VM**을 선택합니다. SSH 접속 프로필은 저장돼 있으므로 주소·키를 다시 입력하지 않습니다.
5. 검증 캐시와 저장된 결과는 유지합니다. VM 내부의 별도 Compose 검증 서비스는 자원을 아끼기 위해 중지했으며, Windows에서 실행 중인 시연 웹과는 독립적입니다.

## 1. Ubuntu 패키지를 직접 가져오기

**자산 현황 → CTI Ubuntu VM → 패키지 수집 실행**를 누릅니다. 작업 완료 후 새 패키지 기록을 확인합니다. 이번 시험에서는 Ubuntu 24.04의 패키지 688개를 읽었습니다. Apache와 MySQL의 바이너리·소스 이름 및 전체 버전을 보여주세요.

설명 예시: “가상 데이터를 입력한 것이 아니라, 등록한 Ubuntu 시험 서버에서 읽기 전용 명령으로 패키지를 가져왔습니다. 수집 시각과 명령 근거를 보존합니다.”

같은 패키지 기록에서 **공식 파일 검증**을 누르고 완료 후 **검증 결과가 담긴 패키지 기록 보기**를 누릅니다. Apache·MySQL의 9개 패키지가 공식 파일과 일치하는지 확인하고 **실행 조건 확인 · Apache HTTP/2**도 보여주세요. 설정 파일 전체가 검증됐다는 뜻은 아닙니다. 검증은 새 기록을 만들므로 **이 새 기록**을 다음 분석에 사용합니다.

설명 예시: “Ubuntu 서명·패키지 해시·실제 파일을 대조합니다. 이 사례에서는 실행 중인 Apache와 HTTP/2 모듈을 공식 파일에 연결하고, VM 내부의 정상 HTTP/2 응답도 확인했습니다. 다른 설정이나 서버 전체의 안전성을 뜻하지는 않습니다.”

## 2. 공식 CVE 자료와 분석 결과·근거 보기

**취약점 분석 → CTI Ubuntu VM → 방금 검증된 패키지 입력 → 분석 실행** 순서로 진행합니다. 입력 시각·ID를 확인해 수집만 한 기록과 구분하세요. 전체 결과 첫 행의 **apache2-bin / CVE-2024-27316 / 영향 있음**에서 **근거 보기**를 누릅니다. 필요하면 CVE 검색을 사용합니다.

검증된 예에서는 설치 소스 버전 `2.4.58-1ubuntu8`, Ubuntu 수정 기준 `2.4.58-1ubuntu8.1`, 출처 `공식 배포본 파일 일치`, 판단 `영향 있음(AFFECTED)`입니다. Ubuntu·Apache의 당시 저장 자료, 출처 링크·수집 시각, HTTP/2 실행 조건을 펼쳐 보여줍니다.

설명 예시: “이 Ubuntu 패키지는 공식 수정 기준보다 낮고, 해당 CVE에 필요한 HTTP/2 활성 조건도 확인됐습니다. 공식 자료와 실제 파일·서비스 관측을 결합한 판단입니다. 공격을 실행하거나 결과를 수동 입력하지 않았습니다.”

검색을 비우고 **추가 확인 필요** 필터도 보여주세요. 수정 기준이 없거나 복잡한 조건을 자동 판단하지 못하면 확인 필요로 남습니다. 결과 건수는 **패키지와 CVE의 조합**이며 서로 다른 CVE 개수와 같지 않습니다. 이번 전체 분석은 영향 있음 1건·수정 기준 충족 1,119건·추가 확인 579건·지원 범위 밖 679건입니다. 확정 조건은 검토한 한 가지 릴리스·버전·CVE·바이너리 조합에만 적용합니다.

## 3. 대응 권고와 학교 LLM 설명·질문

근거 상세의 **대응 권고**에서 공식 수정 기준, 확인할 조건과 조치 후 재수집 절차를 보여줍니다. 이어 **요약 생성**을 누릅니다. 완료 후 한국어 설명, 저장된 원본 판단·버전, A1/E1 등의 인용 버튼을 확인합니다.

질문 답변도 보여주려면 **취약점 인사이트 → CTI Ubuntu VM → 분석 범위 추가에서 방금 완료한 분석 선택** 후 아래 문장을 입력합니다.

> CVE-2024-27316의 저장된 영향 판정과 근거, 우선 확인할 대응 절차를 설명해줘.

**질의 실행**를 누르고 생성된 답변·원본 표·근거 버튼을 확인합니다. 이번 실제 학교 API 질문과 CVE 설명이 모두 성공했습니다. 같은 CVE의 여러 패키지 중 영향 있음 결과가 대표 원본 표에 표시되는 것도 확인했습니다. 문장 형식 검증 실패 시 최대 한 번 같은 근거로 수정 요청하며, 실패 내용을 정상 답변으로 표시하지 않습니다.

설명 예시: “취약점 판단은 저장된 규칙 분석 결과입니다. 학교 LLM은 이 결과와 선택한 공식 근거를 설명합니다. 출처와 원본 값을 같이 확인할 수 있고, AI가 분석 기록을 바꾸지는 않습니다.”

## 4. 보고서 생성과 다운로드

분석 결과의 **보고서 생성**를 누릅니다. 같은 분석이 선택됐는지 확인하고, **AI Summary 포함**을 선택한 뒤 **보고서 생성**을 누릅니다. 완료되면 미리보기를 확인하고 **Markdown 다운로드**를 누릅니다.

보고서에는 자산·입력·판단·대응 권고·공식 근거·검증 이력과 선택한 CVE 설명이 고정됩니다. 자유 질문의 답변은 자동 삽입하지 않습니다. 나중에 자료가 갱신돼도 저장된 보고서는 바뀌지 않습니다.

이번 사례의 실제 다운로드 파일: `D:\CTI-Ubuntu\실제-영향있음-AI포함-보고서.md` (약 4.6 MiB). 이전 `교수님-시연-보고서.md`는 수정 버전 당시의 기록입니다. PDF 출력은 구현하지 않았습니다.

## 이미 준비된 시연 결과

외부 API나 시험 서버가 일시적으로 느릴 때는 **이전에 저장한 결과임을 밝히고** 아래 이력을 선택할 수 있습니다. 새 실행이 성공한 것처럼 설명하지 않습니다.

| 기록               | ID 앞부분  |
| ------------------ | ---------- |
| SSH 수집           | `724006ec` |
| 검증된 패키지 입력 | `95e00d29` |
| 분석               | `826d87d0` |
| 질문               | `91173cec` |
| CVE 설명           | `c51391aa` |
| AI 포함 보고서     | `c3635d9b` |

2026-11-11 01:44~01:57 KST에 저장했습니다. 웹의 시각·ID 앞부분을 보고 선택하세요. 비교용 수정 버전 분석은 `de0a4cdf`, 같은 취약 버전에서 HTTP/2를 끈 분석은 `2be8b3d7`입니다. 기존 실패 이력은 진단을 위해 보존했습니다.

## 문제가 생겼을 때

| 현상                | 시연 중 확인                                                          |
| ------------------- | --------------------------------------------------------------------- |
| 대기 상태가 계속됨  | 작업 내역의 Worker 연결 확인, 별도 Worker 실행 여부                   |
| SSH 시간 초과       | VM 실행·부팅 완료 확인 후 새 수집 요청; 실패 이력은 유지              |
| 일부 수집 표시      | 패키지 목록 완전성과 APT 참고 조회 오류를 구분해 표시                 |
| 검증 중 패키지 변경 | 다시 수집한 새 기록을 검증                                            |
| 학교 API 실패       | 오류 코드 확인, 기존 분석·근거·저장된 설명 사용 가능                  |
| 영향 있음이 안 보임 | 수집 직후 파일·실행 조건을 검증한 새 입력인지, HTTP/2 활성 여부 확인  |
| 결과 없음           | Ubuntu 릴리스·공식 자료 범위·CVE 번호를 확인; 자료 부재는 안전이 아님 |

## 재실행

현재 프로세스가 실행 중이면 중복 실행하지 않습니다. 재부팅 후에는 VirtualBox의 CTI-Ubuntu를 시작한 뒤 PowerShell에서 다음을 실행합니다.

```powershell
cd 'C:\Users\lsu01\Desktop\blended-meshup\cti-agent'
$env:PATH='C:\Users\lsu01\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin;C:\Program Files\nodejs;C:\Users\lsu01\Desktop\blended-meshup\cti-agent\.tools\uv\bin;' + $env:PATH
$env:UV_PROJECT_ENVIRONMENT='D:\cti-agent-runtime\venv'
$env:UV_CACHE_DIR='D:\cti-agent-runtime\cache'
$env:NPM_CONFIG_CACHE='D:\cti-agent-runtime\npm-cache'
$env:TEMP='D:\cti-agent-runtime\tmp'
$env:TMP=$env:TEMP
& 'D:\cti-agent-runtime\venv\Scripts\python.exe' scripts\dev.py
```

실행 창의 Ctrl+C로 해당 실행기가 만든 API·Worker·웹을 종료합니다. 현재 백그라운드 프로세스의 로그와 PID 기록은 `D:\cti-agent-runtime`에 있습니다. VM은 VirtualBox의 시스템 종료 신호로 끕니다. 데이터와 D 드라이브 가상 디스크는 보존합니다.

## 완료로 표시하지 않는 부분

USN·OVAL 전체 조건 해석, 신경망 임베딩 검색, PDF 출력은 미구현입니다. Ubuntu 22.04 실제 서버·다른 아키텍처·외부 원격 서버와 최신 화면 클릭·레이아웃은 이번 인수에서 시험하지 않았습니다. 자동 패치·서비스 재시작·공격 가능성 확정도 제공하지 않습니다. 코드·API·파일의 시험 성공과 이 한계를 구분합니다.
