# 분석 워크스페이스

시연을 시작할 화면은 `/#/workspace`입니다. 개발 실행기에서 기본 서버와 함께 띄울 경우 저장소에 별도 데이터베이스를 설정하고 `python scripts/dev.py --api-port 8011 --web-port 5174`를 실행합니다. 수동 실행 시 마이그레이션 `alembic upgrade head`와 Worker가 필요합니다.

1. **자산 등록**에서 이름과 예상 OS를 입력합니다. SSH 접속 정보와 호스트 키 지문을 저장한 뒤 **SSH 연결 확인**을 누릅니다. 인증키와 허용 주소는 기존 서버 측 설정을 사용합니다.
2. **분석 워크스페이스**에서 서버와 입력을 선택하고 **분석 시작**을 누릅니다. SSH 모드는 새 패키지를 가져온 뒤 지원 패키지의 공식 파일을 대조합니다. 저장 기록 모드는 표시된 수집 시각의 인벤토리를 사용합니다.
3. 네 단계의 상태는 Worker가 DB에 저장한 실행 기록입니다. 페이지를 다시 열어도 진행 상태를 볼 수 있습니다. **집중 보기**는 화면을 넓혀 주고, 완료 후 **기록 재생**은 저장된 단계의 시작 시각을 차례로 보여 줍니다. 동작 줄이기 설정에서는 버튼으로 재생 단계를 넘깁니다.
4. **우선 조치 항목**에서 행을 펼쳐 버전, 조치와 공식 근거를 확인합니다. 건수는 패키지와 CVE의 조합 수입니다. **이 분석에 질문**은 같은 분석을 선택한 상태로 열립니다. **보고서 다운로드**는 해당 실행에서 생성한 Markdown 파일을 내려받습니다.

## 자료와 판정 범위

- 지원 범위는 Ubuntu 22.04·24.04의 Apache2와 MySQL입니다. 실행마다 설치된 대상 소스 패키지별 Ubuntu CVE와 CISA KEV를 갱신하고, Apache가 있으면 Apache HTTP Server 공지도 갱신합니다.
- NVD는 Ubuntu 결과 중 KEV 등재 건을 우선해 CVE 번호순 최대 3건을 보충 조회합니다. MySQL은 해당 Ubuntu 레코드에 연결된 허용된 Oracle 공지 중 최대 2건을 보충 조회합니다. 사용한 기준본, 시각과 한계가 결과에 남습니다.
- 갱신 실패 시 같은 출처·범위의 성공 저장본만 재사용합니다. 필수 Ubuntu 기준본을 확보하지 못한 경우 자료 단계에서 중단합니다. 수집과 공식 파일 대조 사이에 패키지가 변경된 경우 재실행이 필요합니다.
- 보고서는 이번 분석의 규칙 기반 판정과 권고를 사용합니다. 학교 LLM 질문은 사용자가 선택해 실행합니다. 파일 대조를 완료하지 못했거나 적용 조건을 입증하지 못한 항목은 검증 한계를 유지합니다.
- 동시에 같은 자산에 한 번만 실행할 수 있습니다. 관리자 또는 해당 자산에 권한이 있는 담당자가 실행할 수 있으며, 조회자는 결과 조회와 다운로드가 가능합니다.

## API

- `POST /api/v1/assets/{asset_id}/ssh-profile/{profile_id}/check` — 저장된 대상 및 호스트 키로 SSH 인증 확인
- `POST /api/v1/assets/{asset_id}/workflows` — `Idempotency-Key` 헤더와 빈 JSON 객체로 SSH 실행, 또는 `inventory_id`로 저장 기록 지정
- `GET /api/v1/assets/{asset_id}/workspace` — 연결 확인 시각, 실행 단계, 최근 분석·보고서
- `GET /api/v1/assets/{asset_id}/workflows/{run_id}` — 재접속·개별 실행 조회
